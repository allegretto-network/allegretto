The direct rail settles a payment for each request. There is no account to open, no API key to issue, and no prepaid balance: the wallet that signs the payment is the customer, and the price is whatever the service says in the moment.

It is built on [MPP](https://mpp.dev), the Machine Payments Protocol — an open standard for HTTP 402 payments — settling on [Tempo](https://tempo.xyz). Here is the flow:

<Steps>
  <Step title="Request without payment">
    The client calls the service like any HTTP API. The service responds with status `402 Payment
    Required` and a Challenge in the `WWW-Authenticate` header naming the amount, the stablecoin,
    the recipient, and the payment method it accepts.
  </Step>
  <Step title="Sign">
    The client signs the payment with its wallet. A Tempo charge is a signed transfer bound to the
    Challenge, so the amount and recipient cannot be changed after the service issued it.
  </Step>
  <Step title="Retry">
    The client resends the request with a Credential carrying that proof. The service verifies it,
    serves the response, and settles on Tempo. The response carries a `Payment-Receipt` header as
    proof of payment.
  </Step>
</Steps>

Client libraries handle this loop for you. [`mppx`](https://mpp.dev/sdk/typescript) wraps the standard `fetch`, so your code only sees the final response.

## Metered work

A charge settles once per request. An API that meters usage, like an LLM endpoint billed per token, should not settle on chain every time, so MPP's `session` intent opens a payment channel instead. The client funds the channel once, the service issues off-chain vouchers as it serves, and the channel settles on Tempo periodically. Requests add no on-chain latency, and one settlement covers the whole session.

Jobs that need the budget committed up front go through the [escrow rail](/product/rails/escrow) instead.

## From the CLI

`alln mpp` speaks the loop for you. `alln mpp discover` searches for payable endpoints, `alln mpp quote` prints every price an endpoint offers without paying, and `alln mpp fetch` calls one, settling its `402` Challenge from the active wallet.

```sh
alln mpp discover "weather"                                  # find a payable endpoint
alln mpp quote https://api.example.com/weather               # read every price, pay nothing
alln mpp fetch https://api.example.com/weather               # settle it and print the response
```

`quote` reports every offered price — the amount and its currency — without paying, and `fetch --token <address>` picks which quoted currency to pay. The response body goes to stdout, so it pipes into `jq`. The [CLI docs](/tools/cli#mpp) cover the flags.

## Settlement

Payments settle in USD-denominated stablecoins on Tempo. Tempo reaches deterministic finality in roughly 500ms and lets the service sponsor the transaction fee, so a wallet holding only the stablecoin it pays with needs nothing else. The service picks which stablecoin it accepts and names it in the Challenge, so a client never has to guess.
